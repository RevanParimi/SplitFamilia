# SF-001 — Test the balance maths without the network

Priority: **P0** · Task: **T-01** (story 1 of 1) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: none.

Brief: [stage 1 (error handling) and stage 7 (automated tests)](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

The code that works out balances and "who owes whom" moves out of `index.html` into a small
module, `money.js`, and one command tests it on any computer with Node, without touching
Firestore. Nothing changes on screen. For example, Asha pays ₹300 for dinner, split between Asha,
Ben and Chitra: the tests prove the page still says "Ben owes Asha ₹100.00" and "Chitra owes
Asha ₹100.00".

## Acceptance criteria

- `money.js` exports `computeBalances(people, expenses)` and `simplifyDebts(balances)` as pure
  functions: no DOM, no Firebase, no module-level state.
- `index.html` imports them from `./money.js`. The people, ledger and balances it shows are
  unchanged.
- `npm test` runs `node --test` over `tests/`, with no `npm install` and no network.
  `package.json` has no dependencies.
- Characterisation tests pin today's behaviour, including two edge cases: an expense whose payer
  no longer exists is skipped, and a split member who no longer exists is ignored. SF-004 will
  change the second case on purpose.
- `service-worker.js` caches `./money.js`, and the cache name becomes `splitsheet-v3`.
- The "Tests" line in CLAUDE.md names the new command.

## Required tests

Expected values worked out by hand:

- A pays ₹300, split A/B/C → balances A +200, B −100, C −100 → settlements B→A 100, C→A 100.
- A pays ₹90 split A/B/C (30 each), and B pays ₹30 split B/C (15 each) → A +60, B −15, C −45 →
  settlements C→A 45, B→A 15.
- No people, or no expenses → no settlements.
- Break check: change the share formula for a moment, confirm a test fails, then restore it.
