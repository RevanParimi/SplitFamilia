# SF-003 — Production audit baseline, secret scan and .gitignore

Priority: **P0** · Task: **T-02** (story 2 of 5) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: none.

Brief: [stage 1](../brief/2026-09-28-google-play-release-brief.md), including "search for exposed
secrets" and "create/update .gitignore".

## Intended result

One document records, for every production-readiness item in brief stage 1, what the app does
today, the evidence, and which story fixes it, or why the item doesn't apply. A `.gitignore`
stops signing keys, local secrets and build outputs from being committed by accident. For
example, the Firebase web API key at `index.html:472` is recorded as "public by design: restrict
it in Google Cloud Console (manual)". It is not deleted.

## Starting points

- `index.html` lines 465–483 (Firebase SDK from the gstatic CDN, the web config, Firestore
  initialisation).
- The whole git history: 4 commits, 2026-09-04 (IST). No `.gitignore` exists yet.
- The planning session's quick scan found only the Firebase web key. Repeat the scan properly
  and record it.

## Acceptance criteria

- `docs/google-play/PRODUCTION_AUDIT.md` lists every item of brief stage 1 with its finding,
  evidence (file:line) and status. The status is one of: OK; fixed by SF-xxx; not applicable,
  with evidence (for example "no sign-in: nothing imports Firebase Auth"); or **OWNER
  CONFIRMATION REQUIRED**.
- It records at least these known findings:
  - The Firebase web config is public by design. Restricting the key is a manual step.
  - There are no Firestore rules in the repo, and the live rules are unknown → SF-007, D-6.
  - Group names can be guessed → SF-006.
  - An invalid `?g=` link can break the app on every launch → SF-005.
  - Money is split with floating-point maths → SF-004.
  - The Firebase SDK is never cached, so the app can't start offline → SF-008.
  - Users see raw error messages → SF-009.
  - The icon's artwork sits outside the maskable safe zone → SF-012.
  - Android users see iPhone install instructions → SF-010.
  - There is no Android project yet → SF-012 and SF-013.
  - There is no sign-in, token storage, analytics, crash reporting or push, so those items are
    not applicable. Show the grep evidence.
- The full git history is scanned for private keys, service-account JSON, passwords, tokens,
  keystores and `AIza…` keys. The commands and results go in the audit.
- `.gitignore` covers at least:
  - signing keys and their settings: `*.jks`, `*.keystore`, `*.p12`, `keystore.properties`,
    `key.properties`;
  - local config and credentials: `local.properties`, `.env`, `.env.*`,
    `*service-account*.json`, `google-services.json`;
  - build outputs and tooling: `node_modules/`, `.gradle/`, `build/`, `*.aab`, `*.apk`,
    `*.idsig`;
  - Firebase files: `.firebase/`, `firebase-debug*.log`, `firestore-debug*.log`;
  - editor and OS clutter.
- `git ls-files -ci --exclude-standard` prints nothing, so no tracked file becomes ignored.
- No app file changes.
