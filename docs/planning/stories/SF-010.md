# SF-010 — App text and name suit the Android app

Priority: **P1** · Task: **T-03** (story 4 of 5) · Estimate: **1 point**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-009. Owner
decisions: **D-2** (see `open_decisions` in STATE).

Brief: [stage 1 (application name)](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

Inside the installed Android app there is no "Install app" button and no "On iPhone/iPad: open
in Safari…" text. Web visitors still see both. The name shown everywhere matches the name chosen
for the store: **SplitFamilia** (D-2). Today the app shows "Splitsheet".

## Starting points

- `index.html`:
  - the install button (line 394, lines 865–886);
  - the iPhone footer (lines 457–459);
  - the join note (line 383);
  - `<title>`, `<h1>` and `apple-mobile-web-app-title` (lines 6, 14, 375, 391).
- `manifest.json`: `name` and `short_name`.

## Acceptance criteria

- In standalone display mode (`matchMedia('(display-mode: standalone)')`), or when opened by the
  Android app (`document.referrer` starts with `android-app://`), the install button and the
  iPhone line are hidden.
- In a normal browser tab, both behave as today.
- The app name in `manifest.json` (`name` and `short_name`), `<title>`, the headings and
  `apple-mobile-web-app-title` is **SplitFamilia** (D-2, answered 2026-09-28). SplitFamilia is 12
  characters, so it fits `short_name`.
- The cache name prefix `splitsheet-` and the `localStorage` key `splitsheet-group` stay as they
  are. Renaming them would log every phone out of its group. Record this as a decision.
- Bump the service-worker cache name.

## Required tests

- Manual: a normal Chrome tab shows both. The installed PWA (Chrome desktop "Install") shows
  neither. Record screenshots or notes in the receipt.

## Rollout and rollback

- Web deploy with a cache bump. Rolling back is a revert.
