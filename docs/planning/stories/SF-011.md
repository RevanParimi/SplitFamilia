## Intended result

The web app runs as a Railway service at one HTTPS address at the root of a domain: the
Railway-generated `https://<service>.up.railway.app`, or a custom domain. That address serves
`/.well-known/assetlinks.json`, which lets the Android app (SF-012) open full-screen without a
browser address bar. A push to `main` redeploys it (D-5). The container holds only the app's
files: not `docs/`, `android/`, `tests/` or `node_modules/`.

- **Reference: `../StockAgent-main`** (the owner's working Railway app).

## Acceptance criteria

- The `Dockerfile` copies only the app files (`index.html`, `manifest.json`,
  `service-worker.js`, the JS modules, icons, `privacy.html` once it exists, and `.well-known/`),
  and `.dockerignore` backs that up.
- The server listens on `$PORT` and serves dotfile paths (`/.well-known/…`).
- The server sets these headers:
  - `Cache-Control: no-cache` on `index.html`, `service-worker.js` and `manifest.json`;
  - `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy: strict-origin-when-cross-origin`;
  - `Content-Type: application/json` on `assetlinks.json`.
- Optional `railway.json` (config as code): the Dockerfile builder, a healthcheck path, and watch
  patterns so that docs-only commits don't redeploy. The owner applies it in Railway.
- `.well-known/assetlinks.json` names `com.splitfamilia.app` (D-1), with clearly marked
  placeholder SHA-256 fingerprints (`<UPLOAD_KEY_SHA256>`, `<PLAY_APP_SIGNING_SHA256>`) and a
  note on where each comes from. The fingerprints are public, not secret. SF-021 fails the
  release if placeholders remain.
- Existing invite links, and the manifest `id`, `start_url` and `scope`, stay valid. Don't change
  `id` without a recorded reason, because installed copies would treat the app as new.
- No non-local `http://` or `localhost` URLs in the shipped files; a grep checks this.
- Local check: `docker build` and `docker run -e PORT=8080`, if Docker is available, then
  `curl -I` on each file above to show its headers. If Docker is missing, run the same server
  binary directly, or record the gap.
- **Owner steps** go in `docs/google-play/HOSTING_RAILWAY.md`, labelled **MANUAL ACTION
  REQUIRED**:
  1. create the Railway service from this GitHub repo;
  2. enable auto-deploy from `main`;
  3. generate a domain or attach a custom one;
  4. if the Firebase API key gets referrer restrictions later, add the Railway domain.
- Add a `pending_check`: after the first deploy, `https://<host>/.well-known/assetlinks.json`
  returns 200 JSON, and the app loads and syncs over HTTPS.
