# SF-012 — Android app project (Trusted Web Activity)

Priority: **P0** · Task: **T-05** (story 1 of 4) · Estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-010, SF-011.
Owner decisions: **D-0**, **D-1**, **D-2**, **D-8** (see `open_decisions` in STATE).

Brief: [stage 1 (Android items) and stage 6](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

An `android/` project that opens the production site full-screen as an Android app, with the
chosen package name, app name, icon and splash screen. Tapping a shared invite link on the phone
opens it in the app. The web app stays the single source of truth, so a web deploy updates the
Android app too.

## Starting points

- There is no Android project in the repo. The recommended approach (D-0) is a Trusted Web
  Activity generated by Bubblewrap (`@bubblewrap/cli`, run with npx).
  - Capacitor was considered and rejected as the larger change. It would restructure the repo
    and break invite links, because pages would run at `https://localhost`.
- `manifest.json`, `icon-512.png` and `icon-192.png`.
- **Icon finding:** `icon-512.png` is marked `maskable`, but its red seal and paper corners sit
  outside the maskable safe zone (the central circle, 80% of the width). A round Android mask
  clips them.
- Tools: this machine has Node 24 but no JDK or Android SDK. Bubblewrap can download both into
  `~/.bubblewrap`. That needs **D-8**, the owner's OK for the several-GB download.
- Continuous improvement (D-4): with a TWA, every Railway web deploy updates the app on phones
  without a new Play upload. Only changes to the Android wrapper need a new AAB.

## Acceptance criteria

- `android/` is generated by Bubblewrap and committed, with `twa-manifest.json`. The approach and
  its reasons are recorded in `docs/google-play/ANDROID_APPROACH.md`. The risks go there too:
  - the app needs Chrome or another browser that supports TWAs; if verification fails it falls
    back to a Custom Tab with an address bar;
  - Play's minimum-functionality policy.
- `applicationId` is `com.splitfamilia.app` (D-1), the app label is `SplitFamilia`
  (D-2), `versionCode` is 1 and `versionName` is "1.0.0". The web host is the Railway domain
  from SF-011.
- `targetSdk` is the level Google Play currently requires for new apps. Check the official
  "target API level requirements" page and record the date checked (IST). `compileSdk` is at
  least `targetSdk`. `minSdk` is Bubblewrap's default (21 or higher) unless there is a recorded
  reason.
- The merged release manifest has no permission beyond what the TWA needs (`INTERNET`):
  - no `POST_NOTIFICATIONS`, because notification delegation is off;
  - no location;
  - no Play Billing;
  - no `AD_ID`.
  Check it with the merged-manifest output, not by reading the template.
- Cleartext traffic is not allowed.
- Launcher icon: an adaptive icon whose artwork sits inside the safe zone. Create a padded
  `icon-maskable-512.png`, and use it for the manifest's `maskable` entry and for Bubblewrap.
  Bump the service-worker cache name, because the manifest changes.
- Splash background `#F6F4EF`; status and navigation bar `#2F5D50`.
- An intent filter for `https://<host>` with `autoVerify`, so invite links open in the app.
- `./gradlew assembleDebug` succeeds. If an emulator or device is available, the debug app
  installs and opens the site. Without `assetlinks` on the live host it shows an address bar;
  note that.

  `android-app://` referrer or in standalone display mode, and remembers it for the tab

  inject the referrer and `matchMedia` in headless Edge.
