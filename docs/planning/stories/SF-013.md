## Intended result

One Gradle command produces a signed `app-release.aab`. The signing key comes from environment
variables or a git-ignored `android/keystore.properties`, never from git. The owner makes the real
upload key. This story proves the signing path with a throwaway key that never enters the repo.

## Starting points

- `android/app/build.gradle` (from SF-012).
- `.gitignore` (from SF-003).

## Acceptance criteria

- The release build type has `minifyEnabled true` and `shrinkResources true`. R8 keeps what
  `androidbrowserhelper` needs, which the build and a launch check confirm.
- The release `signingConfig` reads, in this order:
  1. the environment variables `SPLITFAMILIA_UPLOAD_STORE_FILE`,
     `SPLITFAMILIA_UPLOAD_STORE_PASSWORD`, `SPLITFAMILIA_UPLOAD_KEY_ALIAS` and
     `SPLITFAMILIA_UPLOAD_KEY_PASSWORD`;
  2. otherwise, the git-ignored `android/keystore.properties`.
- `android/keystore.properties.example` is committed, with placeholders only.
- With no credentials, `bundleRelease` fails with a clear message. It never falls back to the
  debug key.
- `./gradlew bundleRelease` produces `android/app/build/outputs/bundle/release/app-release.aab`.
- The signing path is proven with a throwaway key made with `keytool` in the session scratchpad,
  outside the repo, and deleted afterwards.
- The AAB is verified:
  - `jarsigner -verify -verbose -certs` shows the throwaway certificate;
  - `bundletool validate` passes;
  - `bundletool dump manifest` shows `com.splitfamilia.app`, versionCode 1, the
    required `targetSdk` and only the expected permissions.
- `./gradlew lint` runs on release. Errors are fixed or recorded with a reason.
- `git status` and `git ls-files` show no keystore, properties file, `.aab` or `.apk` tracked.

## Required tests

- Transcripts of each command above.
- A negative check: with the credentials unset, `bundleRelease` fails with the clear message.

## Follow-ups from T-03 (2026-09-29)

- Put the upload key's SHA-256 fingerprint into `.well-known/assetlinks.json` in place of
  `<UPLOAD_KEY_SHA256>` (format `AB:CD:…`, 32 pairs; `npm test` accepts only that format or a
  placeholder). The Play App Signing fingerprint (`<PLAY_APP_SIGNING_SHA256>`) is known only
  after the first upload. Changing the file is a web deploy.
