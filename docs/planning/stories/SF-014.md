# SF-014 — Release build guide, run end to end

Priority: **P0** · Task: **T-05** (story 3 of 4) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-013.

Brief: [stage 6 (BUILD_RELEASE.md, "actually run all reasonable build/test/static-analysis
commands")](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

The owner can follow one document, on their Windows machine, from a fresh clone to a signed
`app-release.aab` made with their own upload key. Every command in it was run in this session
from a clean clone, and the results were recorded.

## Starting points

- The commands and settings from SF-001, SF-007, SF-012 and SF-013.

## Acceptance criteria

- `docs/google-play/BUILD_RELEASE.md` gives the exact commands, in PowerShell with bash
  equivalents where they differ, for:
  1. clean (`./gradlew clean`, removing `node_modules`);
  2. install (`npm ci`);
  3. tests (`npm test`, `npm run test:rules` (removed with Firebase in SF-038));
  4. lint and static analysis (Android lint, plus any web check that exists);
  5. build the release;
  6. generate the `.aab`;
  7. find the `.aab` (its exact path);
  8. verify it (`jarsigner`, `bundletool`).
- The prerequisites are listed with versions: JDK, Android SDK, Node, and how to get each.
- **Creating the upload key**, labelled **MANUAL ACTION REQUIRED**:
  - the `keytool -genkeypair` command (RSA 2048 or stronger, a long validity, alias `upload`);
  - store the keystore outside the repo, keep the passwords in a password manager, and keep a
    backup;
  - fill in `keystore.properties` or set the environment variables;
  - get the SHA-256 for `assetlinks.json`;
  - Play App Signing enrolment, and where to find the app signing key's SHA-256 afterwards.
- A rule: every upload needs a higher `versionCode`, and the doc says where to change it.
- Every command was run from a clean clone (`git clone` into the scratchpad) and its result
  recorded in the receipt. A command that couldn't run is marked "not run: <reason>".

## Required tests

- The clean-clone transcript is the test. Any step that differs from the doc is fixed in the doc
  in this session.
