# SF-015 — Store listing draft and graphics guide

Priority: **P0** · Task: **T-04** (story 5 of 5) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-006, SF-010,
SF-022, SF-023, SF-028, SF-029. Owner decisions: **D-2** (see `open_decisions` in STATE).

Brief: [stage 3](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

A ready-to-paste draft of the Play Store listing that only describes what the app really does,
plus a list of the graphics the owner still has to make, with their exact sizes.

## Starting points

- What the app does today, from `index.html`:
  - start or join a group with a code or link (as changed by SF-006);
  - add and remove people;
  - add an expense with who paid and an equal split among chosen people;
  - delete an expense;
  - set the currency symbol;
  - see the ledger and the simplified "who owes whom";
  - live sync between phones;
  - works offline after the first visit (SF-008).
- Added by planned stories before this one: editing an expense (SF-022), recording a settle-up
  (SF-023), a recent-groups list (SF-029) and the polished UI (SF-028). Use SF-028's after
  screenshots.
- What it does **not** do (the listing must not claim these): accounts or sign-in, unequal or
  percentage splits (unless stretch SF-030 is done), payments of any kind (a settle-up only
  records cash paid outside the app), receipts or photos, notifications, export, reminders.
- Existing graphics: `icon-512.png` (512×512 RGBA), `icon-192.png` and `apple-touch-icon.png`
  (180×180). There is no feature graphic and there are no screenshots.

## Acceptance criteria

- `docs/google-play/STORE_LISTING.md` contains:
  - the app name: **SplitFamilia** (D-2), within the current character limit;
  - a short description and a full description, each within its current limit;
  - a table tracing every claim to a feature in the code (file:line);
  - a category recommendation (for example Finance, Productivity or Travel & Local) with its
    reasoning, marked **OWNER CONFIRMATION REQUIRED**;
  - the main features;
  - a suggested screenshot list: the join screen, people, adding an expense, the ledger, the
    balances, and "All settled up";
  - `<SUPPORT_EMAIL>`, `<SUPPORT_WEBSITE>` and `<PRIVACY_POLICY_URL>` placeholders.
- `docs/google-play/assets/README.md` gives the current required size, format and limits for:
  - the app icon;
  - the feature graphic;
  - phone screenshots (count, aspect ratio, minimum and maximum sides);
  - optional tablet screenshots.
  It cites the official Play Console Help page with the date checked. It says which existing
  file fits (whether `icon-512.png` meets the icon rules) and what is missing.
- Nothing in the listing mentions a feature that doesn't exist. The reviewer checks this against
  the table.

## Required tests

- Character counts for the name and descriptions, recorded in the receipt.
- A cross-check of every claim against the code.

## Graphics from the owner's Claude Design work (2026-09-30)

- `docs/design/playstore-mockups/feature-graphic-1024x500.png` is a candidate feature graphic.
  It is a PNG **with transparency (RGBA)**; check the current rule (Play has asked for JPEG or
  24-bit PNG with no alpha) and, if so, say it must be flattened onto a solid background before
  upload. Its wording must match what the app really does.
- The six `01-welcome.png` … `06-settled.png` (1080 × 1920, RGBA) are **mock-ups** of the
  planned design, not the app. The listing's screenshots must show the real app: use SF-028's
  after shots, taken from the implemented app, and treat the mock-ups only as the layout to
  aim for.
