# SF-016 — Play Console declarations, answered from the code

Priority: **P0** · Task: **T-05** (story 4 of 4) · Estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-007, SF-009,
SF-011, SF-012, SF-023.

Brief: [stage 4 and "Reviewer account"](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

The owner has a prepared answer for every "App content" declaration in Play Console. Each answer
rests on what the code does, and each unknown is flagged instead of guessed. For example,
Financial features is answered "records and calculates shared costs only: no payments,
transfers, wallets, loans or investing", with the evidence.

## Starting points

- Data the app sends to Firestore (`index.html`):
  - people's names (line 776);
  - expense description, amount, payer, split and ISO timestamp (lines 789–795);
  - the currency symbol (line 814);
  - the group code, in the document path.
- `localStorage` holds only the group code (line 494), plus the recent-groups list after SF-029.
  Firestore's persistent cache keeps a copy of the group data on the device (IndexedDB).
- Hosting is Railway (D-3). Its access logs may record visitors' IP addresses. How long they are
  kept is **OWNER CONFIRMATION REQUIRED** (Railway settings and plan).
- Settle-ups (SF-023) only record that cash changed hands outside the app. That keeps the answer
  "no financial features": the app has no payments, transfers or wallets.
- Third parties:
  - Firebase JS SDK 12.17.1 (Firestore, loaded from gstatic);
  - Google Fonts (index.html lines 15–17). Every page load sends the device's IP to Google until
    stretch SF-025.
- None of these exist: sign-in, analytics, crash reporting, ads, push, location, camera,
  contacts, or payments.
- Android permissions: whatever SF-012's merged manifest shows (expected: `INTERNET` only).

## Acceptance criteria

- `docs/google-play/PLAY_CONSOLE_DECLARATIONS.md` has a section for each of:
  - Data safety;
  - Privacy policy;
  - App access;
  - Ads;
  - Content rating (IARC), including whether users share content with each other;
  - Target audience and content;
  - Financial features;
  - Health apps;
  - Sensitive permissions;
  - Account creation and deletion;
  - Advertising ID;
  - News apps;
  - Government apps;
  - any other declaration Play Console currently lists. Check the official list and record the
    date checked.
- Each section answers the brief's 10 questions:
  1. which functionality in this repo affects it;
  2. what data is collected;
  3. why;
  4. whether data leaves the device;
  5. whether it is shared with third parties;
  6. whether it is encrypted in transit;
  7. whether users can delete it;
  8. which SDKs affect it;
  9. the likely Play Console selection;
  10. what needs the owner's confirmation.
- Anything the code can't settle is written **OWNER CONFIRMATION REQUIRED**. That includes:
  - the target age group;
  - the support email;
  - the Firestore location;
  - data retention;
  - whether the owner restricted the API key.
- Data safety uses Google's own data-type definitions, and Firebase's published Play data
  disclosure for what the SDK itself collects. Both are cited with the date checked.
- App access says no login is needed. It gives reviewer steps: start a group, add three people,
  add an expense split three ways, check the balances, delete the expense. Optional:
  `<PLAY_REVIEWER_GROUP_LINK>` for a pre-filled demo group. The link is a capability, so it goes
  only into Play Console, never into git.
- `docs/google-play/REVIEWER_ACCESS.md` repeats those steps and states that no credentials exist,
  so there are no email or password placeholders to fill.
- Consistency with SF-006: if D-4 was declined, the guessable-name risk is stated plainly.

## Required tests

- No "yes" or "no" appears without evidence or an OWNER CONFIRMATION marker.
