# SF-019 — Release testing guide

Priority: **P0** · Task: **T-06** (story 3 of 5) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-004, SF-006,
SF-009, SF-013, SF-022, SF-023, SF-029. Owner decisions: **D-7** (see `open_decisions` in STATE).

Brief: [stage 7](../brief/2026-09-28-google-play-release-brief.md).

## Intended result

A practical checklist the owner and testers follow on real phones before each release, matched
to what this app actually does. It also explains the path Internal testing → Closed testing →
Production, including the extra closed-testing rule that may apply to a new personal developer
account.

## Starting points

- The features listed in SF-015, and the worked money examples in SF-004.

## Acceptance criteria

- `docs/google-play/RELEASE_TESTING.md` covers each item in brief stage 7. Items the app doesn't
  have are marked **Not in this app**, with a one-line reason:
  - registration, login and password reset: there are no accounts;
  - logout: "Switch group" is the nearest equivalent, so test that;
  - account deletion;
  - editing expenses, unless SF-022 is done;
  - recording a settlement, unless SF-023 is done;
  - notifications;
  - session expiry.
- Each test has steps and an expected result worked out by hand. For example: ₹100 split three
  ways → the balances show ₹66.67 owed to the payer, as ₹33.34 + ₹33.33.
- The guide covers:
  - offline and slow network (the Android emulator's network settings, or Chrome remote
    debugging);
  - backend errors (an invalid group, rules denial);
  - app restart;
  - deep links (an invite link opens the app);
  - Android versions (min, target and one in between);
  - screen sizes (a small phone, a large phone, a tablet);
  - testing the **Play-signed build from the internal testing track**, not a debug build.
- The Internal → Closed → Production flow: who to invite, how testers opt in, and what to check
  at each stage.
- The current closed-testing requirement for new personal accounts (a number of testers opted in
  for a number of continuous days), marked **VERIFY IN PLAY CONSOLE**, citing the official page
  with the date checked.
- All automated tests (`npm test`, `npm run test:rules`) are run in this session, with the
  results recorded in the receipt.

## Required tests

- The automated suites pass, with their transcripts in the receipt.
- A dry run of the manual checklist on the local site in a browser, to catch steps that don't
  match the UI.
