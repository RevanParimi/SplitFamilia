## Intended result

readiness report in the brief's format. It says exactly what is done and what is still
outstanding, and it gives the exact path of the AAB only if this session built it.

## Acceptance criteria

- The whole tree and git history are searched for each item in the brief's final audit list:
  - API keys, passwords and tokens;
  - private keys, signing keys and keystores;
  - development, `localhost` and non-local `http://` URLs;
  - debug flags;
  - TODOs that affect production;
  - excessive Android permissions (from the merged manifest);
  - test credentials;
  - Firebase or service credentials.
  The commands and results are added to `PRODUCTION_AUDIT.md`.
- Each hit is classified: real secret, public by design (with the reason), documentation example
  or placeholder. Real secrets are escalated to the owner, not quietly rewritten out of history.
- It checks that `assetlinks.json` placeholders are replaced, or flags that they are not.
- `npm test`, `npm run test:rules` (removed with Firebase in SF-038), Android lint and `bundleRelease` are re-run in this session.
  The build is reported as a success only if it succeeded in this session.
- `docs/google-play/READINESS_REPORT.md` has these sections:
  - Changes Made;
  - Build Status, with the exact AAB path or the exact blocker and the next command;
  - Tests;
  - Security Findings;
  - Play Console Manual Actions;
  - Owner Confirmation Required;
  - Ready / Not Ready, as lists of complete and outstanding technical requirements.
- The same report is given to the owner in chat.
