## Acceptance criteria

- The whole tree and git history are searched for each item in the brief's final audit list:
  - API keys, passwords and tokens;
  - private keys, signing keys and keystores;
  - development, `localhost` and non-local `http://` URLs;
  - debug flags;
  - TODOs that affect production;
  - excessive Android permissions (from the merged manifest);
  - test credentials;
  - Firebase or service credentials.
  The commands and results are added to `PRODUCTION_AUDIT.md`.
- Each hit is classified: real secret, public by design (with the reason), documentation example
  or placeholder. Real secrets are escalated to the owner, not quietly rewritten out of history.
- It checks that `assetlinks.json` placeholders are replaced, or flags that they are not.
- `npm test`, `npm run test:rules` (removed with Firebase in SF-038), Android lint and `bundleRelease` are re-run in this session.
  The build is reported as a success only if it succeeded in this session.
- `docs/google-play/READINESS_REPORT.md` has these sections:
  - Changes Made;
  - Build Status, with the exact AAB path or the exact blocker and the next command;
  - Tests;
  - Security Findings;
  - Play Console Manual Actions;
  - Owner Confirmation Required;
  - Ready / Not Ready, as lists of complete and outstanding technical requirements.
- The same report is given to the owner in chat.

## Follow-ups from the T-05 review (2026-10-02)

See [the T-05 review](../evidence/T-05-review.md). Both are small changes to `android/`; do them
before the bundle the owner uploads, in one rebuild.

- **F-15 (low):** the release build's resource shrinker removes `res/raw/web_app_manifest.json`.
  Bubblewrap ships it so that Chrome OS can install the web app without a network request
  ([bubblewrap#88](https://github.com/GoogleChromeLabs/bubblewrap/issues/88)), and Bubblewrap's
  own template doesn't shrink resources. Phones are not affected. Fix: add
  `android/app/src/main/res/raw/keep.xml`,
  `<resources xmlns:tools="http://schemas.android.com/tools" tools:keep="@raw/web_app_manifest" />`
  (a file of ours that `bubblewrap update` leaves alone; mention it in ANDROID_APPROACH.md's
  file table). Rebuild and check that `app/build/outputs/mapping/release/resources.txt` no longer
  lists `raw:web_app_manifest` and that `jar tf` shows `base/res/raw/web_app_manifest.json`. Or
  record the loss as accepted.
- **N-18 (note, optional):** `android/manifest-checksum.txt` is the SHA-1 of `twa-manifest.json`
  with LF endings, but a Windows checkout gives it CRLF. Add `twa-manifest.json text eol=lf` to
  `android/.gitattributes`, so Bubblewrap doesn't see a changed manifest on the owner's clone.
