# SF-027 — Web lint and automatic checks on every push (stretch)

Priority: **P2** · Task: **T-07** (story 5 of 5) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-001, SF-007,
SF-013. **Stretch:** do it only if the owner promotes it.

## Intended result

Every push to GitHub runs the tests, the rules tests, a web lint and an unsigned Android release
build, so a broken change is caught before it reaches the family's phones.

## Starting points

- `package.json` scripts (SF-001, SF-007) and `android/` (SF-012, SF-013).

## Acceptance criteria

- ESLint, with an HTML plugin for the inline module, passes on `index.html` and the JS modules
  (`npm run lint`).
- A GitHub Actions workflow runs `npm ci`, `npm test`, `npm run lint`, `npm run test:rules` (removed with Firebase in SF-038) and
  an unsigned `bundleRelease`.
- The workflow has no signing secrets and uploads no artifacts to Play.
- Adding the workflow file goes through a push, which is the owner's word (CLAUDE.md §5).

## Required tests

- The workflow passes on a branch push, which the owner authorises.

## Rollout and rollback

- Repo change. Roll back by deleting the workflow file.
