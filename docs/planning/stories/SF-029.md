# SF-029 — Keep a list of your recent groups

Priority: **P1** · Task: **T-04** (story 3 of 5) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-006.

## Intended result

A family with a Goa trip and a Diwali-party group can switch between them in one tap. Today,
"Switch group" forgets the current group (`localStorage.removeItem`), so getting back needs the
invite link again. Once codes are unguessable (SF-006), that means real lost access.

## Starting points

- `index.html`: `resolveGroupId()` (lines 490–498), "Switch group" (lines 521–526) and the join
  screen (lines 373–385).
- The one `localStorage` key today is `splitsheet-group`.

## Acceptance criteria

- Each opened group is remembered on this device only, in a new `localStorage` list of codes and
  last-opened times. The current-group key stays as it is.
- The join screen shows "Your groups", most recent first. Tapping one opens it.
- "Switch group" goes back to that list and no longer forgets the group. Each entry has "Remove
  from this device", which never deletes cloud data.
- The list is capped (proposal: 20). Invalid entries are dropped, using the SF-005 validator.
- The list logic is a pure module tested with `node --test`.
- Bump the service-worker cache name.
- The privacy docs (SF-016, SF-017) note that group codes are stored on the device.

## Required tests

- Pure tests:
  - adding an existing code moves it to the top with no duplicate;
  - the cap drops the oldest entry;
  - invalid entries are ignored;
  - removing one entry leaves the rest in order.
- Manual: open two groups, switch between them, then remove one → the other stays.

## Follow-up from the T-02 review (2026-09-29)

- Tapping a recent group is a third way to open a group from the join screen. Since T-02, groups
  open in the same page, and finding F-3 showed that two opens in one page load leave the page
  listening to both groups. SF-009 fixes this first; keep its "one group per page load" rule for
  this path too. See [the T-02 review](../evidence/T-02-review.md).

## Follow-ups from T-03 (2026-09-29)

- SF-009 fixed F-3: `openGroup()` and `startApp()` return at once when a group is already open
  (`appStarted`), and "Start group" is disabled while a "Join" check runs. A recent-group tap
  goes through `openGroup()` and so gets the same rule. T-03's browser check
  (`evidence/T-03-browser-check.mjs`, F1 and F2) shows the pattern to test it with.

## Rollout and rollback

- Web deploy with a cache bump. Rolling back is a revert. The extra `localStorage` key is
  harmless if left behind.
