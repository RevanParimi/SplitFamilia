# SF-031 — A small Node server on Railway replaces Caddy

Priority: **P0** · Task: **T-08** (story 1 of 4) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-011. Owner
decisions: **D-13** (see `open_decisions` in STATE).

## Intended result

The Railway service runs one small Node.js server instead of Caddy. For now it serves exactly the
same files with the same headers, so nothing changes for the family. The API (SF-033) and live
updates (SF-034) are added to this same server. For example, `https://<host>/` still shows the
SplitFamilia start screen, and `/.well-known/assetlinks.json` is still JSON.

Why: the owner's direction of 2026-09-30 is to move the database to Railway too, with no
dependency on Firebase. The data needs a server, and one Node server keeps it to one Railway
service, like StockAgent.

## Starting points

- `Dockerfile`, `.dockerignore`, `Caddyfile`, `railway.json` (SF-011).
- `tests/wiring.test.js` (the Docker and shipped-file checks) and
  `docs/planning/evidence/T-03-caddy-headers.txt` (the headers to keep).
- Node 24 on this machine has `node:http` and `node:sqlite` built in. No framework is needed.

## Acceptance criteria

- `server.js` (a new top-level file, or `server/` if it grows) uses only Node's built-in modules.
  It listens on `$PORT` (8080 if unset) and serves the app's files from the image.
- The same headers as the `Caddyfile` on every file: `Cache-Control: no-cache`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `application/json` on `assetlinks.json`, and correct content types for `.html`, `.js`,
  `.json` and `.png`. ETags or `Last-Modified` give quick 304s on revalidation. Compression is
  optional.
- Everything else returns 404, with the same headers: `docs/`, `tests/`, `package.json`,
  `firestore.rules`, `server.js` itself, any `..` path and any dotfile other than
  `/.well-known/assetlinks.json`.
- `GET /healthz` returns 200. `railway.json` uses it as the health check.
- The `Dockerfile` uses `node:24-alpine` and copies only the app's files and the server. The
  `Caddyfile` is removed. `tests/wiring.test.js` still checks the image against the worker's
  `SHELL` and still rejects `http://` and `localhost` in shipped files.
- The page is unchanged (it still uses Firebase until T-09). No cache bump is needed unless a
  cached file changes.

## Required tests

- `node --test` starts the server in-process on a free port and checks each file's status and
  headers, the 404 list above (including `/../package.json` and `/%2e%2e/`), and `/healthz`.
- A break check: remove `nosniff`, confirm a test fails, then restore.

## Rollout and rollback

- A push to `main` deploys it (the owner's word). It serves the same page, so phones see no
  change. Roll back with Railway's "Redeploy" on the last Caddy deployment, or a revert.
