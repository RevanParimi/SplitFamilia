# SF-032 — The ledger's database: SQLite on a Railway volume

Priority: **P0** · Task: **T-08** (story 2 of 4) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-031. Owner
decisions: **D-13**.

## Intended result

Groups, people and expenses are stored in one SQLite file on a Railway volume, which survives
deploys and restarts. This is what StockAgent does. Money is stored as whole paise, so ₹100.00
is `10000` and never a decimal. For example, after a redeploy every group's people and expenses
are still there, and Railway keeps a backup copy of the volume.

## Starting points

- `node:sqlite` (`DatabaseSync`), built into Node 24. No npm package is needed.
- `money.js` (`toPaise`, `MAX_AMOUNT_PAISE`) and `group-code.js` (the code pattern).
- Today's data shapes: see SF-007's card and `firestore.rules`.

## Acceptance criteria

- `db.js` (or `server/db.js`) opens `<DATA_DIR>/splitfamilia.db`. `DATA_DIR` is
  `RAILWAY_VOLUME_MOUNT_PATH` when Railway sets it, otherwise `./data` (git-ignored). It turns on
  WAL mode and foreign keys.
- The schema is created by numbered migrations that run at start, each once (a `schema_version`
  table). Tables:
  - `groups`: `code`, `currency`, `created_at`;
  - `people`: `group_code`, `id`, `name`, `created_at`;
  - `expenses`: `group_code`, `id`, `date`, `description`, `amount_paise` (an integer),
    `paid_by`, `created_at`;
  - the split: ordered IDs, in a table or a JSON column; record the choice.
- IDs are the client's (Firestore's 20-character IDs, and new `crypto.randomUUID()` ones).
  Writing the same ID twice is harmless: the second write is ignored. This is what makes offline
  replays safe (SF-036).
- Every query uses bound parameters, never string-built SQL.
- **MANUAL ACTION REQUIRED**, in `HOSTING_RAILWAY.md`:
  - add a volume to the service, mounted at `/data`;
  - turn on the volume's backups (**VERIFY IN RAILWAY**: the plan and the menu names);
  - pick the service's region. Southeast Asia (Singapore) is recommended for a family in
    India. A volume stays in its region.
- If the file can't be opened, the server still serves the page, and the API answers 503 with a
  plain code. The logs say why, without any group code.

## Required tests

- `node --test` with a temporary database file:
  - migrations run once, and a second start changes nothing;
  - a round trip of a group, people and an expense keeps `amount_paise` exactly (3334 in, 3334
    out; 1000000000 in, 1000000000 out);
  - a duplicate ID is ignored;
  - a code or name holding `'` or `;` is stored as text.
- A break check: build one query by string concatenation, and confirm the quote test fails.

## Rollout and rollback

- It ships with T-08 and holds nothing until the API writes to it. Rolling back leaves the file
  on the volume untouched.
