# SF-034 — Live updates from the server

Priority: **P0** · Task: **T-08** (story 4 of 4) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not in this card. Dependencies: SF-033.

## Intended result

When one phone adds an expense, every other phone showing that group sees it within about a
second, as with Firebase today. For example, Asha adds "Taxi ₹50" and Ben's ledger shows it
without a reload.

## Starting points

- The API from SF-033 and its group version number.
- Railway's proxy supports long-lived HTTP responses.

## Acceptance criteria

- A streaming endpoint (Server-Sent Events format) sends the group's version at once, and again
  after every change to that group. Every 25 seconds it sends a comment line, so proxies don't
  close the connection.
- The page reads it with `fetch` streaming, so the group code can go in a header (SF-033), and
  not with `EventSource`, which can't send headers.
- Each connection is for one group. Closing it frees its memory. A server restart drops every
  connection, and pages reconnect with a growing delay (1 s, 2 s, 4 s, … up to 30 s).
- There is at most one live connection per open page.

## Required tests

- Two clients on one group: one `POST`s an expense, and the other hears the new version within
  1 s. A client on another group hears nothing.
- 100 connections opened and closed leave no listeners behind.
- The heartbeat arrives while nothing changes. The test sets a short interval.

## Rollout and rollback

- It ships with T-08.
- **MANUAL ACTION REQUIRED, at the end of T-08:**
  - the volume, its backups and the region (SF-032);
  - then the owner's word to push. After the push, a check: `/healthz` answers 200, and the
    page still opens as before.
